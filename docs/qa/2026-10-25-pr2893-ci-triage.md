## Local fix for the introduced type error

The root TS program includes Bun types, which augment `typeof fetch` with
`preconnect`. A plain callable wrapper and `vi.fn<typeof fetch>` implementations
therefore do not implement that interface, although Node/Vitest execution passed.

- Gateway transport now proxies the actual fetch callable. Its runtime properties
  remain available, while the apply trap still strips provider Authorization,
  preserves body/URL/method/signal, and forces `redirect: 'error'`.
- Shared test-only `mockFetch` carries an inert `preconnect` spy. It cannot open
  connections. No casts or global type declarations weaken the contract.
- New regression verifies that the proxy preserves and delegates the runtime
  extension without issuing a fetch request.
- Capturing fetch at provider construction is a minor change from the former
  late global lookup; it matches the stable Worker runtime and tests install their
  mocks before constructing the provider.

Fresh read-only review found no blocker: auth removal, redirect protection,
cancellation and direct-provider behavior remain intact.
